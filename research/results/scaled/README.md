## What this shows

**Correctness holds at every tier**: zero lifecycle errors (authorize →
capture → refund failures) across all 25 runs and 1,250+ total request
cycles in this sweep — the safety/liveness properties established in
`research/formal-model/` and the smaller-scale results in
`research/results/` are not an artifact of only testing at low concurrency.

**Honest saturation point, reported rather than hidden**: throughput grows
roughly linearly from VUS=1 through VUS=100 (4.8 → 157.8 req/s), then
_plateaus and destabilizes_ at VUS=250 — both mean throughput and its
variance get markedly worse (137.8 ± 30.9 req/s, down from 157.8 ± 9.4 at
VUS=100; p95 latency variance triples). This is a **resource-saturation
effect of this specific reference deployment** (a single, unclustered
Node.js process and its connection pool to a single local Postgres
instance) — not a defect in the idempotency protocol itself, which never
produces an incorrect or undefined response even as raw performance
degrades. A production deployment would horizontally scale the API layer
before ever reaching this point; this artifact intentionally does not claim
otherwise, and reports the actual measured ceiling of the reference
implementation as it stands rather than omitting the tier where it appears.
